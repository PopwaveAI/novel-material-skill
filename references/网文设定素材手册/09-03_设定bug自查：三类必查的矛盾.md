# 9.3 设定 bug 自查：三类必查的矛盾

> 素材来源：novel-material-skill ·《网文设定素材手册》9.3 设定 bug 自查：三类必查的矛盾

设定 bug 大多不是“写错了”，而是“前后不一致”。三类最常出现，按类排查最有效。

表 9-3　三类设定矛盾与排查方式

| 类型 | 表现 | 排查方式 |
|---|---|---|
| 物理矛盾 | 距离、时间、天气、伤势前后不符 | 列出关键事件的日期与地点，逐条核对 |
| 规则矛盾 | 同一规则在不同章节效果不同 | 把规则写成条文，逐条检索全书 |
| 人物矛盾 | 能力、权限、关系忽然变化 | 给每个主要角色建一张“能力与权限”卡 |

距离核算法：把全书地图简化成节点与天数。每一次移动都先查表，不靠感觉。

时间轴核算法：用一条横轴记录关键事件日期。节日、季节、伤势恢复期都挂在轴上。

伤势核算法：重伤至少影响一到三章的战斗力，且留下后遗症。不能第二天满血。

钱粮核算法：给主角一本简单的账。进多少、出多少、还剩多少，写清三次就能防住大半漏洞。

权限核算法：谁能调兵、谁能开仓、谁能进内院。权限一旦写定，就不能因为剧情需要而临时放宽。

自查最有效的时机不是完稿后，而是每写完一卷。此时记忆还热，改起来成本最低。
